# Project Context

## Vision

This project is not intended to behave like:

- a generic developer portfolio
- a startup landing page
- a dashboard-like showcase
- a technology playground

It should behave more like:

- a curated digital publication
- an editorial product
- a premium interactive experience
- a carefully directed technical narrative

---

## Core Objective

The portfolio exists to:

- communicate technical maturity
- demonstrate product thinking
- showcase architectural intentionality
- express engineering discipline
- present thoughtful execution

The goal is not feature quantity.
The goal is perceived quality.

---

## Experience Philosophy

The experience should feel:

- calm
- intentional
- restrained
- readable
- technically confident
- editorial

The interface should avoid:

- noise
- clutter
- unnecessary interactions
- excessive animations
- dashboard aesthetics
- portfolio template patterns

---

## Product Positioning

This portfolio is intended to function as:

- a hiring entry point
- a product design statement
- an engineering quality demonstration
- a narrative of technical reasoning

Every implementation decision must reinforce this perception.

---

## Epic 2 Focus

- Curate and surface Works as an editorial selection, not a gallery.
- Strengthen narrative clarity in work detail pages.
- Maintain calm hierarchy and reduce visual noise.

## Epic 2 Success Criteria

- Works order is intentional and justified by the narrative.
- Work detail pages lead with clear context (title, description, role, date).
- No new visual noise or dashboard patterns are introduced.
