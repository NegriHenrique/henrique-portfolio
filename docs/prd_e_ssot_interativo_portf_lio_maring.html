2. Sistema de Design & Governança de Interface (OKLCH + Tailwind v4)

Esta seção permite explorar interativamente a gestão matemática de cores do projeto. Abandonamos modelos tradicionais (RGB/HSL) para adotar exclusivamente o espaço perceptual **OKLCH** com gamut estendido **Display P3** e fallback gracioso para sRGB.

Inspetor Dinâmico de Tokens de Design

Tailwind CSS v4 CSS-First (@theme)

Clique nos tokens abaixo para inspecionar os parâmetros de Luminosidade (L), Croma (C) e Matiz (H) do espaço **OKLCH**, garantindo uniformidade perceptual de contraste.

Variável CSS-First: --color-surface-base
Definição OKLCH: oklch(0.15 0.02 250)
Gamut de Cor: Display P3 (com Fallback sRGB)
Razão de Contraste WCAG: 12.4:1 (Aprovado AAA)

Por que OKLCH em vez de HSL/RGB?

No modelo HSL, a manipulação de saturação distorce a luminosidade percebida (um amarelo a 50% de luz aparenta ser drasticamente mais brilhante que um azul no mesmo percentual).

O **OKLCH** é construído sobre a percepção biológica humana. A Luminosidade (L) garante contraste consistente independentemente do tom (Hue), eliminando "zonas de gradiente lamacento" durante transições.

Tipografia Fluida: clamp() 1.50rem (24px)

7. Protocolos Analíticos de QA & Regressão Visual

Para imunizar a interface contra distorções visuais durante refatorações de código, a pipeline de CI/CD do projeto integrará **Visual Regression Testing** automatizado utilizando **Playwright** e **Chromatic**. Cada Pull Request executará varreduras pixel-a-pixel comparando a saída das ilhas de componentes com os gabaritos do Figma.

1. Playwright Test: Captura automática de snapshots em 360px, 768px e 1920px.
2. Chromatic Cloud: Comparação diferencial de pixels (Diff Threshold < 0.01%).
3. CVA Validation: Validação de variância de classes utilitárias no Tailwind v4.
